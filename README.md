# openJiuwen Challenge’26

Харнесс решает задачи по математике, поиску, анализу данных и исправлению Python-кода. На вход он получает каталог задач и общий бюджет токенов. Готовый ответ сразу записывается в answer.txt рядом с task.json.

## Сборка и запуск

Для сборки достаточно Docker. В образе закреплены Python 3.11.18, openJiuwen 0.1.19 и версии зависимостей. Пакеты загружаются при сборке.

```sh
docker build -t jiuwen-challenge .
```

Укажите в TASKS абсолютный путь к каталогу задач. Экспортируйте адрес прокси в LLM_BASE_URL, ключ в LLM_API_KEY и лимит в BUDGET. Если лимит не задан, харнесс использует 100 000 токенов. Процессу в контейнере нужны права на запись в каталоги задач. Команда ниже предполагает, что сеть hack-net уже создана и в ней доступен прокси.

```sh
docker run --rm --network hack-net \
  -e LLM_BASE_URL -e LLM_API_KEY -e BUDGET -e HOME=/tmp \
  -v "$TASKS:/data/tasks:rw" \
  --read-only --tmpfs /tmp:rw,size=2g \
  --cap-drop ALL --security-opt no-new-privileges \
  --cpus 8 --memory 16g --pids-limit 512 \
  --workdir /app --entrypoint python \
  jiuwen-challenge /app/run_agent.py --tasks-dir /data/tasks
```

## Как выбираются задачи

Харнесс читает тип, условие и reward из task.json. Данные берёт из workspace текущей задачи. Сначала Python обрабатывает знакомые вычисления, таблицы и связи между записями. В задачах на исправление кода он запускает исходные тесты и проверяет подходящие локальные правки.

Для оставшихся задач харнесс вызывает qwen3.8-27b-noreason. После первого круга qwen3.8-27b может повторить неудачную попытку с учётом предыдущего ответа. Внутри круга выше стоит задача с большим отношением reward к ожидаемой стоимости запроса. По умолчанию одновременно выполняются до трёх запросов. Вызовы моделей идут через openJiuwen и заданный прокси.

Для числовых задач модель может вернуть Python-вычисление, для таблиц также подходит SQL. При поиске по текстовым карточкам харнесс сверяет выбранное значение со строкой источника. Правку кода он проверяет в копии рабочей папки, записывает в разрешённые файлы и повторно запускает исходные тесты. Только после этого появляется ответ DONE. В конце харнесс использует оставшееся время для локального перебора исправлений.

## Бюджет и пропуски

Стоимость запроса равна числу входных токенов, делённому на 10, плюс число выходных токенов. Токены рассуждения входят в число выходных. Перед запросом харнесс резервирует бюджет, после ответа сверяет расход с полем usage. На случай ошибки оценки он оставляет запас 5%. Если связь оборвалась после отправки и usage неизвестен, в расход идёт весь резерв этого запроса.

Если для ответа не хватает обязательного файла или значения, либо исходные тесты противоречат друг другу, харнесс может пропустить задачу. Неизвестный формат передаётся следующему решателю, пока хватает времени и токенов. У задач без решения файл answer.txt не создаётся. Запись готового ответа выполняется атомарной заменой файла.

## Траектории

В [примере публичного прогона](trajectories/public.jsonl) каждая строка содержит идентификатор задачи, запрос, ответ модели, результат проверки и расход токенов. Восемь задач дали 20 из 20 баллов. Локальные решения без вызова модели отражаются в stderr. Там же в конце прогона выводится строка TOKENS с общим расходом.

Чтобы сохранить траектории своего прогона, добавьте к параметрам docker run следующий фрагмент. Переменная TRACES должна содержать абсолютный путь к доступной для записи папке на хосте. Результат появится в файле trajectory.jsonl.

```sh
-e HARNESS_TRAJECTORIES=/trajectories -v "$TRACES:/trajectories:rw"
```
